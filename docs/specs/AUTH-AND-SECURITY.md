# 인증 및 보안 상세 계약 (AUTH-AND-SECURITY)

## 1. 범위와 명시적 위험 수용
- 회원가입: ID, 비밀번호, 표시 이름. 로컬 PC별 독립 계정 저장. 관리자의 매핑 수정 권한은 일반 로그인과 별도 승인.
- **사용자 확정 정책:** `ID만 입력 → 새 비밀번호 설정`을 허용한다. 성공 시 해당 계정의 개인 Jira API 토큰 **삭제** 및 현재 실행 프로세스가 보유한 모든 해당 계정 세션 무효화. 별도 본인 확인은 하지 않는다.
- 이 정책은 **타인 계정 침해 및 DoS를 예방하지 않는다**. 토큰 삭제만으로는 공격을 막지 못하며 현재 사용자 승인으로 위험을 수용한 상태다. 실사용 전 조직 보안 담당자의 정책 적합성 확인 필요. 사용자 ID를 아는 사람 누구나 타인 비밀번호를 재설정할 수 있음을 UI와 매뉴얼에 명시.
- 재설정 작업은 `토큰 제거 → 비밀번호 해시 교체 → 세션 무효화`를 하나의 논리 트랜잭션으로 다루되 OS Credential Manager 제거 실패 시 비밀번호 변경을 성공으로 보고하지 않는다. Windows 계정이 다르면 타 사용자 Windows Credential Locker에 접근할 수 없으므로 **PC/Windows 프로필별 계정·토큰 범위와 복구 제약을 명시하고 실패 시 완료 처리하지 않는다**.
- 세션은 앱 프로세스에 한정한다. 다중 프로세스 사용 가능성에는 세션 버전(`credential_version`)을 영속 저장해 이전 로그인 버전 무효화한다.

## 2. 비밀번호/키 분리
- 비밀번호 검증은 개별 16바이트 이상 랜덤 salt와 PBKDF2-HMAC-SHA256을 사용. 반복 횟수는 고정 10만 회가 아니라 구성 가능한 파라미터(`algorithm`, `iterations`, `salt`, `version`)로 저장하고 성능 측정 후 정한다. 해시 비교에는 `hmac.compare_digest` 사용.
- 매핑 암호화 키는 사용자 로그인 비밀번호와 분리. 매핑 DB는 *관리자 비밀번호에서 파생한 키*로 복호화하면 관리자 비밀번호 변경 시 DB 복호화 문제를 만들 수 있으므로, 랜덤 DEK를 생성해 인증된 관리자 비밀번호 KDF로 KEK를 만들고 DEK를 래핑하는 형태로 구현. 변경 시 래핑만 갱신한다. 초기 관리자 비밀번호 설정, 별도 보호된 복구 키/백업 정책을 작업 시작 시 승인 게이트로 다룬다.
- 무인 검색을 위해 DB가 앱 시작 시 자동 복호화되어야 한다면 관리자 비밀번호 기반 암호화만으로는 충족 불가. 이 경우 Windows DPAPI로 래핑한 키를 해당 Windows 사용자 컨텍스트에서 읽는 구조를 사용하고, 관리자 비밀번호는 GUI 변경 권한 통제에 사용한다. **현재 기본 설계는 DPAPI 래핑된 로컬 DEK + 관리자 GUI 인증 분리**. DPAPI가 비밀을 완벽히 보호하는 것은 아니며 동일 Windows 계정의 공격자/프로세스가 접근할 수 있다.
- 관리자 비밀번호 최초 생성은 설치 후 최초 관리자 진입 시 생성. 분실 시 암호화 DB를 자동 초기화하지 말고 복구 불가/재가져오기 안내. 관리자 비밀번호의 신원 확인 없는 재설정은 제공하지 않는다.

## 3. 저장 및 무결성
- `grafana_db.dat`, `n3r_db.dat`: `schema_version`, `key_id`, `nonce`, `ciphertext`, `auth_tag`가 포함된 인증된 암호화(예: AES-GCM 또는 Fernet) 컨테이너. 고정 키·고정 nonce 금지. 원본은 항상 암호문.
- 쓰기: 임시파일 작성 → flush/fsync(가능한 경우) → `.bak` 보관 → atomic replace; 실패 시 원본 유지. 민감 데이터 `.bak`도 암호문.
- 토큰: **Jira 계정별** Windows Credential Manager 또는 DPAPI로 보호. 텍스트 설정·로그·샘플·Git에 절대 저장하지 않는다. 비밀번호/토큰은 표시/로그/오류 출력 시 마스킹.
- 암호화는 외부 파일 편집을 물리적으로 불가능하게 만들지 않는다. 인증 태그 무결성 검증으로 임의 수정/손상을 탐지하고 백업 복구를 안내한다.
- 실행 파일 폴더 변경·Windows 사용자 프로필 변경·PC 교체 시 DPAPI가 복호화 불가능할 수 있으므로 매핑 원본 Excel 백업과 승인된 내보내기/재가져오기 절차를 준비한다.

## 4. 인증 오류·테스트
- 사용자 ID 중복, 빈 ID/암호, 재설정 중 토큰 제거 실패, 비밀번호 해시 포맷 오류, 데이터 손상, 관리자 비밀번호 변경, OS 사용자 변경, `.bak` 복원 실패를 검증한다.
- 로그인 반복 실패 시 짧은 제한·UI 경고를 둘 수 있으나 로컬 오프라인 비밀번호 재설정 정책이 남아 있음을 숨기지 않는다.
- **실운영 게이트:** 이 설계가 사내 정보보호 정책과 일치하는지 최종 검토 필요.
