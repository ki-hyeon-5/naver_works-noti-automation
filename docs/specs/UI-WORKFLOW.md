# PySide6 UI 워크플로우 계약

## 1. 화면 구성
- 로그인/회원가입/비밀번호 재설정; 메인 입력/미리보기/상태; 관리자 암호 확인 후 Grafana·N3R 2탭 CRUD; 설정(토큰, 에픽, 기본/알람별 참조자, 로그 경로 및 연월 폴더 ON/OFF).
- 메인: 클립보드 입력 → 파서 → NoData 제외 건수 표시 및 별도 파싱 실패 건수 표시 → 담당자/출처 확인 → 개별/묶음 라디오 → 노티 미리보기/수정 → 검토완료 → 등록 승인.
- **자동 등록 모드 없음**. 사용자가 승인하지 않는 한 Jira create 호출 금지.

## 2. 미리보기·검토
- 필수 노티 요소 `서비스명`, `장애현상`, `발생시간`을 확인 및 수정 가능, 조건부 클러스터 상단. `Target`·시간 누락은 경고 표시. 단순 문자열에서 '[확인필요]'을 지우는 것만으로 검증 완료로 간주하지 말고 구조화된 필드를 검증한다.
- 미매칭: 기본 담당자를 채우고 알림 1회(한 입력 배치의 해당 건수 포함), 수동 변경 가능. 기본 담당자 없는 경우 등록 불가.
- 이중 매칭: 담당자 동일해도 출처 선택을 요청하며, 다르면 담당자와 출처 모두 선택.
- NoData는 **검토 영역에 들어가지 않음**. 총 입력건/정상건/NoData 제외/파싱 실패 건 통계 표시.
- 개별 등록은 알람별 독립 상태·담당자·제목·참조자; 묶음 등록은 4대 조건을 충족하는 알람만 그룹. 조건 미충족 자동 분할을 미리보기에서 명시.
- 건별 검토 체크 및 전체 검토/전체 등록 버튼 제공. 전체 등록은 등록 가능 항목만 일괄 승인 처리하며 등록 불가 사유를 건별 표시.

## 3. 키 및 등록 안전장치
- `QPlainTextEdit`의 Enter는 줄바꿈. 제출은 명시적 `[등록]` 버튼 또는 `Ctrl+Enter`만 허용. 입력 편집 중 Ctrl+Enter 단축키도 **미리보기 검토 완료+승인 화면이 활성**인 때만 등록 실행.
- 등록 실행 전 재차 요구: 필수값 유효, 담당자 식별 가능, 출처 충돌 없음, NoData 제외, Jira 연결 검증, 중복 재등록 시 추가 확인.
- 등록 중 버튼 비활성화; API 백그라운드 워커 사용. 일부 결과 실패 시 정상 건을 반복 생성하지 않는다.
- 등록 화면에 개별 상태(PENDING/REQUESTING/DONE/PARTIAL_FAILED/UNKNOWN/FAILED), Jira 키, 다음 사용자 조치를 표시.

## 4. 묶음 결정성과 재검토
- 묶음 4조건: 사용자 묶음 선택, 담당자 동일, 비어있지 않은 동일 태그, 같은 Target 또는 정제 Alert Name.
- 이 관계는 비추이적이므로 **전체 그룹 구성원 모든 쌍이 호환**되어야 한다. 원본 입력 순서로 안정적으로 그룹 생성하되 알람 순서가 바뀌면 결과가 달라질 수 있음을 표시. 사용자가 그룹 변경 시 재검토 후 승인.
- 그룹 내 서로 다른 Alert Name일 때 본문은 각 알람의 블록을 그대로 연결하고 제목은 첫번째 정제 Alert Name과 `외 N건` 규칙.
