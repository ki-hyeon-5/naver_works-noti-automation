# 아키텍처 및 비즈니스 결정 기록 (ADR)

---

## ADR-01: PyInstaller onedir 배포 방식 채택
- **결정:** 단일 파일 `onefile` 요구를 폐기하고 `onedir` 폴더 압축 배포를 채택한다.
- **이유:**
  1. `onefile`은 매 실행 시 `%TEMP%\_MEIxxxx`에 압축을 해제하므로 시작 지연(3~5초)이 발생함.
  2. 실행 파일 외부의 `data/`, `config/` 디렉터리에 로컬 DB를 영속화하여 앱 재시작 및 업데이트 시 데이터 보존이 용이함.
  3. 사내 보안 백신의 오탐 가능성을 크게 낮춤.

## ADR-02: 비밀번호 분실 시 토큰 초기화형 즉시 재설정 (위험 수용)
- **결정:** 별도 본인 인증 없이 ID 입력만으로 비밀번호를 재설정하되, 기존 저장된 개인 Jira API 토큰을 영구 삭제(초기화)한다.
- **이유:** 소규모 내부 근무자 환경의 편의성을 위해 채택되었으나, 계정 탈취 및 서비스 방해(DoS) 위험이 상존함을 인정하고 문서화함.

## ADR-03: '확인 후 등록' 단일 모드 운영 (자동 등록 모드 폐기)
- **결정:** 설정 화면의 '자동 등록' 모드를 삭제하고 오직 '확인 후 등록' 단일 모드로 운영한다.
- **이유:** 자동 모드에서도 최종 Enter 승인을 요구하도록 합의되었으므로 두 모드 간 실질적 차이가 없으며, 관제 오등록 방지를 위해 사용자의 최종 검토 단계가 필수적임.

## ADR-04: 다중 알람 묶음 4대 조건 강제
- **결정:** 담당자 일치, 출처 태그 일치, `Target` 일치 또는 `Alert Name` 일치, 묶음 선택 시에만 묶음 등록을 허용한다. 조건 불일치 시 독립 이슈로 강제 분할한다.

## ADR-05: 별도 로컬 사용자 데이터 위치
각 Windows PC/사용자별 `%LOCALAPPDATA%/NotiAutomation`에 암호화 DB·설정을 영속 저장하며 `onedir` 배포 폴더를 교체해도 정보가 보존되도록 한다. 로그 경로는 사용자가 선택 가능하다.

## ADR-06: Jira 자동 등록 제거와 등록 장부
자동 Jira 등록 모드는 없고 미리보기·검토 이후 명시적 승인만 허용한다. API 요청 전 등록 시도를 장부에 기록해 UNKNOWN/부분실패 및 재시작 복구를 관리한다.

## ADR-07: 묶음 비추이성 안전 규칙
출처 태그가 없는 건은 묶지 않는다. 그룹 구성원 전원 간 묶음 적합성을 검사하고, 입력 순서에 따른 그룹 결과를 미리보기에서 검토·승인한다. 실제 그룹 분할 알고리즘 변경 시 테스트 및 사용자 검토가 필요하다.
