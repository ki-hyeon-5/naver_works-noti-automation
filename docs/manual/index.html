01

시작하기

시스템 개요 및 포터블 실행 가이드

Windows 11용 NotiAutomation/ 폴더를 원하는 위치에 풀고 NotiAutomation.exe를 실행합니다. 사용자 PC에 Python이나 외부 데이터베이스를 설치할 필요가 없습니다. 압축 폴더는 통째로 옮길 수 있지만 사용자 데이터는 Windows 사용자 프로필의 %LOCALAPPDATA%/NotiAutomation/에 저장됩니다.

업데이트

앱을 종료하고 배포 폴더를 새 버전으로 교체합니다. %LOCALAPPDATA%/NotiAutomation/의 data/와 config/를 삭제하지 마세요. 같은 Windows 사용자 프로필에서 재실행합니다.

현재 버전은 Grafana 알람만 처리합니다. SCP 알람은 지원하지 않습니다. Jira 화면의 MOCK- 키는 로컬 시뮬레이션 결과이며 실제 이슈 키가 아닙니다.

02

접근 관리

계정 관리 및 비밀번호 재설정

  1. 회원가입 탭에서 ID, 이름, 비밀번호를 입력합니다.
  2. 로그인 탭에서 ID와 비밀번호를 입력합니다.
  3. 분실 시 비밀번호 재설정 탭에서 ID와 새 비밀번호를 입력하고 ID로 비밀번호 재설정을 누릅니다.
계정 탈취·서비스 방해 위험

현재 정책은 ID만 알면 비밀번호를 재설정할 수 있습니다. 재설정 즉시 해당 계정의 개인 Jira API 토큰이 삭제되고 기존 로그인 세션이 무효화되지만, 이 조치가 계정 탈취 위험을 없애지는 못합니다. 토큰은 다시 입력해야 합니다.

03

입력

알람 원문 복사 및 자동 파싱

Grafana 관제 표에서 알람 행의 값을 드래그해 복사한 뒤 메인 입력창에 붙여넣고 알람 분석을 누릅니다. 줄바꿈과 탭이 불규칙해도 Firing, Start At 일시, Duration을 기준으로 알람 경계를 찾습니다.

No Data 값이 NoData이거나 Alert Name이 DataSourceNoData인 건은 검토 목록과 등록 대상에서 제외됩니다. 화면의 제외 건수·사유를 확인하세요. 파싱 실패 건은 별도로 표시되며 NoData로 간주하지 않습니다.

확인필요 항목

Target이 비었거나 -이면 대상없음, Start At 형식이 잘못되면 시간오류로 표시됩니다. 수정·검토 저장에서 구조화된 값을 고치기 전에는 등록할 수 없습니다.

04

출력 형식

표준 노티 문구와 Jira 제목

노티 미리보기는 다음 형식입니다. 신뢰할 수 있는 클러스터 | 상세내용 패턴일 때만 클러스터 줄이 추가됩니다.

클러스터 : namespace  (있는 경우에만)

서비스명 : server-01

장애현상 : CPU high

발생시간 : 26-10-11 01:57

Duration은 노티에 넣지 않습니다. 묶음 노티는 알람별 블록을 빈 줄로 연결합니다. Jira 제목에서는 Alert Name 앞의 연속 대괄호와 끝의 심각도 소괄호를 제거합니다.

예시[Linux] CPU high (WARNING)→[247][GRAFANA] server-01, CPU high

Grafana 매칭은 [247][GRAFANA], N3R 매칭은 [247][N3R]를 씁니다. 양쪽 모두 미매칭이면 출처 태그를 빼고 [247]만 붙입니다. 양쪽 모두 매칭되면 출처 태그를 직접 선택합니다.

05

등록 승인

확인 후 등록과 묶음 등록

  1. 목록에서 알람을 선택해 Target, 장애현상, Start At, 클러스터, Jira accountId, 출처 태그와 노티 본문을 확인합니다.
  2. 필요한 값을 고치고 이 알람 검토 완료를 체크한 뒤 수정·검토 저장을 누릅니다. 전체 검토는 적격 건의 검토 표시를 돕습니다.
  3. 개별 등록 또는 묶음 등록을 고릅니다. 묶음 등록이면 묶음 구성 확인으로 분할 결과를 확인합니다.
  4. 선택 등록 또는 전체 등록을 누릅니다. 전체 등록은 적격 건만 전송하며 차단 건은 이유를 표시합니다.

노티 편집창에서 Enter는 줄바꿈입니다. Ctrl+Enter는 선택 등록을 요청하지만 검토·승인 조건을 통과해야 합니다. 자동 등록 모드는 없습니다.

묶음의 4가지 조건
  1. 묶음 등록을 선택했다.
  2. 담당자가 동일하다.
  3. 비어 있지 않은 출처 태그가 동일하다.
  4. Target 또는 정제된 Alert Name이 동일하다.

모든 구성원 쌍이 조건을 만족해야 합니다. 불일치 건은 개별 이슈로 분할됩니다.

당일 동일한 Target | 정제 Alert Name | Start At은 중복 경고 후 명시적으로 확인한 경우에만 다시 등록됩니다. UNKNOWN(생성여부불명)과 PARTIAL_FAILED(부분실패)는 일반 중복 확인으로 우회할 수 없습니다. Jira에서 생성 여부와 기존 이슈를 수동 대조하세요. 생성 후 담당자·참조자 후속 작업이 실패해도 새 이슈 생성은 자동 재호출되지 않습니다.

등록 중에는 Mock Jira 요청 중…이 표시됩니다. 결과 목록의 DONE, PARTIAL_FAILED, UNKNOWN, FAILED 상태와 MOCK- 키를 확인하세요. 현재 실 Jira 전송은 제공하지 않습니다.

06

매핑 관리

담당자 매칭과 관리자 2탭

상단 관리 메뉴의 관리자 매핑을 엽니다. 최초에는 최초 관리자 비밀번호 설정 후 관리자 승인을 누릅니다. 승인 전 Grafana·N3R 탭은 비활성화됩니다.

각 탭에서 매핑 행 검색, 행 추가, 선택 행 수정, 선택 행 삭제를 사용합니다. 변경 뒤 알람 분석을 다시 실행해 새 매칭을 적용합니다. 실제 Jira accountId가 없으면 담당자를 선택해도 등록할 수 없습니다.

충돌 처리

두 DB가 모두 매칭되면 담당자가 같아도 출처를 선택해야 합니다. 담당자도 다르면 담당자와 출처를 함께 선택합니다. 미매칭이면 유효한 기본 담당자를 적용할 수 있고, 설정이 없거나 유효하지 않으면 등록이 차단됩니다.

07

데이터 가져오기

Excel 가져오기와 중복 검출

관리자 승인 후 Grafana 또는 N3R 탭에서 Excel 가져오기를 눌러 해당 DB용 파일을 선택합니다. 가져오기 중 버튼이 잠기며 기존 DB에 행을 추가(Append)합니다. 원본 Excel은 수정하지 않습니다.

동일 키·동일 내용은 건너뛰고, 동일 키에 담당자나 내용이 다르면 자동 덮어쓰지 않습니다. 충돌 창에서 신규 반영(예), 기존 유지(아니오), 결정 보류(취소)를 행별로 고릅니다. 오류·충돌 건수를 확인한 후 매핑 탭을 다시 확인하세요.

08

운영과 복구

설정, 로그와 문제 해결

관리 → 사용자 설정에서 로그 경로·연월 폴더, 기본 담당자 이름과 Jira accountId, 복수 에픽과 기본 에픽, 기본·알람별 참조자, 보고자, 개인 Jira 토큰을 관리합니다. 토큰은 다시 표시되지 않고 별도 Windows 보호 저장소에 보관됩니다. 실 Jira 필드 매핑은 미검증이며 Mock 상태입니다.

로그 저장 위치
  1. 설정한 경로
  2. C:\noti-log
  3. %LOCALAPPDATA%\NotiAutomation\logs

연월 폴더 ON: YYYY\MM\YYYY-MM-DD.txt · OFF: YYYY-MM-DD.txt. 모두 실패해도 이미 받은 등록 결과는 바뀌지 않으며 비영구 기록 실패 경고를 확인해야 합니다.
