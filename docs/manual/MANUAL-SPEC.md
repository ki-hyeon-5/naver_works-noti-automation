# 오프라인 HTML 사용설명서 설계 규격 (MANUAL-SPEC.md)

---

## 1. 오프라인 웹 기술 제약
- **file:// 프로토콜 동작:** 외부 CDN(Bootstrap, FontAwesome 등) 및 `fetch()` 비동기 로딩을 절대 사용하지 않는다.
- 모든 CSS, JavaScript, 목차 데이터는 `index.html` 내부에 인라인 또는 상대 경로 로컬 파일로 완결한다.

## 2. 8대 필수 수록 섹션
1. **시스템 개요 및 포터블 실행 가이드**
2. **계정 관리 및 비밀번호 재설정 정책 (토큰 초기화 주의사항)**
3. **알람 원문 복사 및 앵커 기반 자동 파싱 (NoData 제외 안내)**
4. **표준 노티 문구 및 Jira Summary 정제 규칙**
5. **확인 후 등록 워크플로우 및 묶음 등록 4대 조건**
6. **담당자 매칭 충돌 대처 및 관리자 2탭 매핑 DB 관리**
7. **Excel 가져오기(Append) 및 중복 검출 가이드**
8. **환경설정, 3단계 Fallback 로그 확인 및 문제 해결(FAQ)**

## 개정된 검증 규칙
- `file://` 직접 열 때 외부 CDN/모듈 fetch/원격 font, 외부 JS/CSS 의존 금지. 패키징에 CSS, JS, 이미지 리소스를 함께 포함하고, 출력된 onedir dist에서 실제 실행 파일이 매뉴얼을 열 수 있어야 한다.
- 실제 앱의 UI 문구와 동일한 스크린 안내 사용; NoData 제외·비밀번호 재설정 위험·개별/묶음 4조건·Jira UNKNOWN/부분실패·로그 위치를 명확히 안내. SCP는 1차 미지원으로 명시.
- Task 5 화면 문구: `알람 분석` 후 입력·검토·NoData 제외·파싱 실패 건수를 확인한다. `Target`, `장애현상`, `Start At`, `클러스터`, `Jira accountId`, `출처 태그`를 구조화된 필드에서 정정하고 `수정·검토 저장`을 누른다. 노티 편집창 Enter는 줄바꿈이며 `Ctrl+Enter`는 선택 등록을 요청한다. `전체 검토`, `선택 등록`, `전체 등록`, `묶음 구성 확인`은 별도 조작이다. 현재 실행 진입점은 `MOCK-` 키만 발행하며 실 Jira 전송을 하지 않는다.
- Task 6 화면 문구: 시작 시 `로그인`·`회원가입`·`비밀번호 재설정` 탭이 표시된다. 재설정 화면에는 ID만으로 타인 계정 재설정이 가능한 미해결 위험과 토큰 삭제 안내를 표시한다. 메인 `관리` 메뉴에서 `관리자 매핑`을 열면 비밀번호 승인 전 두 탭이 비활성화된다. 승인 뒤 `Grafana`·`N3R`에서 검색, `행 추가`, `선택 행 수정`, `선택 행 삭제`, `Excel 가져오기`를 사용한다. 충돌은 신규 반영·기존 유지·결정 보류 중 선택한다. `사용자 설정`은 로그 경로·연월 폴더·기본 담당자·에픽·기본/알람별 참조자·보고자·개인 토큰을 관리한다. 토큰은 화면에 다시 표시되지 않고 설정 JSON에 저장되지 않는다. 실 Jira 필드는 검증 전 Mock 상태다.
- Task 7 화면 문구: `선택 등록`·`전체 등록` 후 `Mock Jira 요청 중…`을 표시하고 등록 버튼을 잠근다. 결과 목록에 `DONE`/`PARTIAL_FAILED`/`UNKNOWN`/`FAILED`와 `MOCK-` 키를 표시한다. 부분실패·생성여부불명 건에는 Jira 수동 대조 조치를 보여주고 일반 중복 재등록 확인으로 우회하지 않는다. 등록 장부는 `%LOCALAPPDATA%/NotiAutomation/data/registration_journal.json`에 남아 재시작 후 차단을 복원한다. 실제 Jira 전송은 제공하지 않는다.
- 좌측 목차, 검색, 8개 필수 섹션은 로컬 브라우저 수동 확인과 `tests/test_task8_manual_docs.py` 정적 검증을 둘 다 수행.
